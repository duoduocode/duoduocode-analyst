## 3. 阵容图设计

### 3.1 布局

- **单张全场图**：mplsoccer Pitch（`pitch_type="opta"`），纵向球场（left-to-right）。
- **主队占据下半场**（靠近自己球门，y=0~50），**客队占据上半场**（y=50~100）。
- 球员按 `grid` 字段落位：
  - `grid` 格式 `"col:row"`，如 `"2:3"` 表示第2列(后卫线)第3行。
  - `col` 映射 y 坐标：1=GK(门前), 2=DEF, 3=DEF/DM, 4=MF/AM, 5=FW。
  - `row` 映射 x 坐标：左到右展开。
- **中场线**用虚线标注双方半场分界。

### 3.2 球员显示

| 元素 | 呈现方式 | 规格 |
|------|------|------|
| 头像 | `OffsetImage` 圆形裁剪，贴到 pitch 坐标 | 直径 ≈ 4.5 pitch 单位 |
| 号码 | 头像右下角圆形徽章 | 直径 1.5，白色底 + 队色字 |
| 姓名 | 头像下方，姓氏（last name）优先 | 字号 5.5pt，浅灰色 |

### 3.3 头像缓存策略

```
output/cache/player_photos/{player_id}.png
```

- 优先读本地缓存
- 未命中则 HTTP GET `photo_url`，写入缓存
- 下载超时 10s，失败降级为纯色圆点 + 号码

### 3.4 队徽

- 每个半场的上方/下方放置队徽（`team.logo_url`），直径约 8 pitch 单位
- 队徽下方标注阵型（如 `4-3-3`）

### 3.5 替补席

- 主队替补居左（x=0~8%），客队替补居右（x=92%~100%）
- 已登场球员标注 `↑`，绿色高亮

### 3.6 颜色配置

| 元素 | 颜色 |
|------|------|
| 场地底色 | `#122b1e`（深草绿） |
| 场地线条 | `#3a6b4a` |
| 主队球员 | `#2ecc71` |
| 客队球员 | `#3498db` |
| 背景底色 | `#1a1a2e` |

## 4. 一句话总结

### 4.1 生成方式

在 `prompts/tactical.yaml` 的 `【战术定论】` 之后新增一个独立段落：

```yaml
  【一句话总结】
  - 60-80 字。提炼比赛最核心的矛盾、反差与张力感。
  - 必须引用 1-2 个关键数据（控球率、比分数、射门数、xG等）来支撑矛盾点，不能空洞抒情。
  - 用对比反差结构：数据维度 A vs 数据维度 B，形成张力。
  - 风格参考：
    "75%的控球率、21脚射门——巴黎织了一张密不透风的传控之网，但枪手全场仅一次射正就穿透了它。"
    "九十分钟轰出25脚射门无一命中，加尔各答红队却在补时最后一秒用角球带走了三分。"
```

### 4.2 数据传递

在 `src/composer/tactical_prompt.py` 的 `build_tactical_system_and_user` 中：

1. 同一个 system prompt 在一次 LLM 调用中输出五段叙事 + 一句话总结
2. 解析时用正则提取 `【一句话总结】` 段落
3. 返回值从 `tuple[str, str]` 改为 `tuple[str, str, str]`（增加 one_liner）
4. 在 `run_tactical_only.py` 中将 `one_liner` 传给 HTML builder

### 4.3 失败回退

- 如果 LLM 未输出 `【一句话总结】`，用模板填充：`"{home} {score_home}-{score_away} {away} — {stage_name}"`
