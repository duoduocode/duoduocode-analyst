# 融合比赛报道 — 技术方案

## 1. 概述

融合报道将**战术数据分析** + **视觉解析（热力图/传球方向）** + **新闻素材**编织为一篇赛事报道文章，同时生成配套战术图表。最终产出 Markdown（含图片引用）和 HTML 两个版本。

**启动命令**：
```bash
python generate_fusion_report.py 19609180          # 完整版
python generate_fusion_report.py 19609180 --no-news  # 跳过新闻素材
python generate_fusion_report.py 19609180 --no-html  # 跳过 HTML
```

---

## 2. 核心架构

```
generate_fusion_report.py (主入口)
    │
    ├── ① 数据加载层
    │   ├── load_raw_data()          → RawMatchData (球员/事件/统计)
    │   ├── load_news()              → 赛前/赛况/赛后新闻文本
    │   └── load_vision_cache()      → 视觉解析缓存 (热力图+传球方向)
    │
    ├── ② 计算引擎层
    │   ├── compute_tactical_analysis()   → 战术数据 (match_flow / coaching / signals)
    │   └── vision_analyzer.run_vision_analysis() → 逐人视觉解析 (无缓存时)
    │
    ├── ③ 叙事生成层 (LLM)
    │   ├── generate_tactical_narrative()   → 战术叙事 (4 段: 画像/演绎/验证/博弈)
    │   └── generate_pressing_narrative()   → 压迫叙事 (3 段: 布局/回报/代价)
    │
    ├── ④ 空间合成层 (代码)
    │   ├── build_player_spatial_portrait()   → 球员空间行为 (12人数据卡)
    │   ├── build_team_tactical_synthesis()   → 球队战术合成 (三路通道+阵型+枢纽)
    │   └── build_pressing_spatial_context()  → 压迫空间上下文
    │
    ├── ⑤ 图表生成层
    │   └── plot_tactical_synthesis()         → tactical_synthesis.png
    │
    └── ⑥ 融合写入层 (LLM)
        ├── build_fusion_prompt()             → 组装最终 prompt
        ├── llm.generate()                    → 融合报道正文
        └── generate_fusion_html()            → HTML 输出
```

## 3. 数据流

```
原始数据 (raw_data.json)
    │
    ├── 球员热力图 PNG ──→ vision_analyzer (豆包视觉模型) ──→ vision_cache.json
    │                        逐人提取: 活动区域、传球方向、带球推进距离
    │
    ├── 球员统计 (SportMonks) ──→ player_insights_v6 ──→ 评分/射门/传球/推进
    │
    └── 事件/趋势 (events + trends) ──→ tactical_insights ──→ match_flow / coaching
        │
        ▼
    compute_tactical_analysis()  → tactical_data (dict)
        ├── match_flow:    ppda, possession, shots, xg (逐窗口/全场)
        ├── coaching:      style_clash, 阵型线索, 对位分析, 攻守比例
        └── signals:       战术信号 (识别压节奏/闪击/反击/阵地战等)
```

## 4. 核心模块

### 4.1 战术叙事生成 (`src/composer/tactical_prompt.py`)
- Prompt: `prompts/tactical_prompt.yaml`
- 输入：tactical_data 原始结构化数据
- 输出：4 段分析文本（画像 / 演绎 / 验证 / 博弈）

### 4.2 压迫叙事生成 (`src/composer/pressing_prompt.py`)
- Prompt: `prompts/pressing_prompt.yaml`
- 输入：ppda_trend, possession_trend, shot_segments, def_actions, goal_events + 压迫空间上下文
- 输出：3 段分析文本（布局 / 回报 / 代价）

### 4.3 视觉解析器 (`src/engine/vision_analyzer.py`)
- 逐个读取球员热力图 PNG，调用豆包视觉模型逐人解读
- 提取：活动高频区域、传球方向（前/横/回 + 长/短）、带球推进距离、触球区域
- 缓存到 `vision_cache.json`

### 4.4 空间合成器 (`src/composer/spatial_summary.py`)
核心功能：

- **build_player_spatial_portrait()**：为 Top 12 球员生成结构化数据卡
  - 活动区域、传球向前/横向/回传、推进距离、触球数、射门/进球/xG

- **build_team_tactical_synthesis()**：球队级进攻体系合成
  - 进攻倾向描述（重心在中路/偏左/偏右）
  - 三路通道分级（主力方向 / 辅助通道 / 次要通道）
  - 控制枢纽（重叠最多的区域 + 核心球员）
  - 阵型线索（防线高位/靠后、边卫参与度、前锋回撤）

### 4.5 战术合成图 (`src/visualizer/tactical_sketch.py`)
- 球场背景 + 中线 + 方向箭头（队名 + 比分）
- **三路方块**：home(x=14→56)、away(x=64→106)，宽度统一 42px
  - 颜色深浅表示占比高低（深绿 ≥40%、中绿 ≥25%、浅绿 <25%）
  - 标签格式：「左路 30%」条内贴边，字号 15pt
- **阵型线索行**（y=-5）：防线高位/靠后 | 边卫参与进攻 | 前锋回撤/顶前
- **传球倾向条**（y=-14）：向前(绿)/横向(黄)/回传(红) 三段彩色条 + 百分比

## 5. 融合报道 Prompt (`prompts/fusion_report.yaml`)

### 5.1 输入数据
| 类别 | 内容 |
|------|------|
| 比赛信息 | 赛事、场地、对阵、比分 |
| 新闻素材 | 赛前背景 / 赛况 / 赛后评论 |
| 战术指标 | 控球/射门/xG/PPDA/压迫强度/攻守比例 |
| 走势数据 | 逐窗口控球率、射门分布、压迫变化 |
| 事件时间线 | 进球/红黄牌/换人/var，含已知信息限制 |
| 战术叙事 | 4 段战术分析（LLM 生成） |
| 压迫叙事 | 3 段压迫分析（LLM 生成） |
| 战术合成 | 进攻倾向 + 三路通道 + 枢纽 + 阵型 + 球员数据卡（代码生成） |

### 5.2 输出结构
```
# 标题（LLM 自拟）
## 开篇钩子          (100-150字)
## 战术速写          (500-700字，含 [配图0] + [配图1])
## 走势拆解          (200-250字，含 [配图2])
## 压迫博弈          (150-200字，含 [配图3])
## 胜负手            (150-180字)
## 收尾              (80-100字)
```
全文 1000-1300 字。

### 5.3 核心禁令（写作约束）
1. **严禁虚构**：只写已知信息中的事件细节，不脑补射门方式/助攻/对话/氛围
2. **禁止罗列球员名单**：不写「9人中路覆盖」，写「进攻重心压在中路」
3. **禁止技术术语**：不出现「热力图」「热区」「PPDA」「zone」等
4. **数字格式**：一律阿拉伯数字
5. **图表钩子**：4 张配图必须按规范引用 + 读图说明
