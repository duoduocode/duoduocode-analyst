# 关键事件判定方案 (Key Event Detection)

> 版本: v1.0  
> 日期: 2026-06-08  
> 适用范围: 球员贡献分析系统 (v6 + 旧版 player_insights + signals)

---

## 1. 四类关键事件

| 事件 | 英文名 | 分值 | 定义 |
|------|--------|------|------|
| **首开纪录** | First Goal | +2.0 | 对于分出胜负的比赛，获胜方打进的第一球；对于平局的比赛，双方各自的第一球 |
| **绝平球** | Equalizer | +3.0 | 比赛以平局结束，导致最终平局的进球发生在比赛结束前 5 分钟内（含加时赛） |
| **制胜球** | Winning Goal | +4.0 | 比赛以 1 球分差分出胜负，打进这一球的进球者 |
| **绝杀** | Late Winner | +4.5 | 制胜球 + 进球时间在比赛结束前 5 分钟内 |

> **注意**：绝杀和制胜球是同一球的递进关系。绝杀 = 制胜球 + 时间条件。计分时只取最高（绝杀 4.5，制胜球 4.0，不叠加）。

---

## 2. 详细判定规则

### 2.1 首开纪录 (First Goal)

**触发条件：**
- 比赛分胜负：获胜方按时间顺序打进的第一球
- 比赛平局：双方各自打进的第一球（各自队伍的"首开纪录"）

**不触发：**
- 0-0 比赛（无进球）

**示例：**
| 比分 | 进球顺序 | 首开纪录 |
|------|---------|----------|
| 2-1 (主胜) | H1(10'), A1(30'), H2(75') | H1 |
| 2-2 (平) | H1(10'), A1(30'), H2(55'), A2(88') | H1, A1 |
| 0-3 (客胜) | A1(20'), A2(40'), A3(80') | A1 |

### 2.2 绝平球 (Equalizer)

**核心定义：** 比赛以平局结束，且导致最终平局的进球发生在比赛结束前 5 分钟内。

**判定流程：**
1. 比赛必须是平局（包括常规时间结束平局，以及加时赛后平局）
2. 跟踪比分进程，找到"使比分扳平"的那一球
3. 此球发生的时间必须在最后 5 分钟内

**时间判定：**
- 常规时间结束平局：`time_elapsed ≥ 90 - 5 = 85`
- 加时赛后平局：`time_elapsed ≥ 120 - 5 = 115`（加时赛结束前 5 分钟内的扳平球）

**不触发：**
- 非平局比赛
- 平局但扳平球不在最后 5 分钟（如第 40 分钟扳平，此后双方再无进球）
- 0-0 的比赛

**示例：**
| 比分 | 进球顺序 | 绝平球 | 原因 |
|------|---------|--------|------|
| 1-1 | H1(10'), A1(88') | A1 | 88' 扳平，在最后 5 分钟 |
| 1-1 | A1(10'), H1(40') | 无 | 40' 扳平，不在最后 5 分钟 |
| 2-2 | H1(10'), A1(30'), A2(55'), H2(90') | H2 | 90' 扳平，在最后时刻 |
| 1-1 (加时) | H1(20'), A1(116') | A1 | 加时赛 116' 扳平 |

### 2.3 制胜球 (Winning Goal)

**核心定义：** 比赛以 1 球分差结束（不论常规时间还是加时赛），导致最终领先的那一球。

**判定流程：**
1. 比赛分差必须为 **1 球**（如 1-0, 2-1, 3-2 等）
2. 如果分差 > 1（如 2-0, 3-1），则**没有制胜球**
3. 跟踪比分进程，找到"使胜方领先且之后再未被追平"的那一球
4. 如果是交替领先（如 1-0 → 1-1 → 2-1），制胜球是让胜方最后一次领先的那球（第 2 球）

**不触发：**
- 平局
- 分差 ≥ 2 球的比赛

**示例：**
| 比分 | 进球顺序 | 制胜球 | 原因 |
|------|---------|--------|------|
| 1-0 | H1(55') | H1 | 唯一进球 |
| 2-1 | H1(10'), A1(30'), H2(80') | H2 | 80' 打破平局 |
| 1-0 (加时) | H1(105') | H1 | 加时赛唯一进球 |
| 3-1 | H1(10'), H2(20'), A1(60'), H3(90') | 无 | 分差 = 2 |
| 2-1 | H1(10'), A1(30'), H2(40') | H2 | 40' 反超后再无进球 |

### 2.4 绝杀 (Late Winner)

**核心定义：** 制胜球 + 进球时间在完整比赛时间结束前 5 分钟。

**判定流程：**
1. 先判定是否存在**制胜球**
2. 如果有制胜球，检查其时间是否在最后 5 分钟内
3. 时间阈值取决于比赛结构：
   - 无加时赛：`time_elapsed ≥ 90 - 5 = 85`（常规时间最后 5 分钟）
   - 有加时赛：`time_elapsed ≥ 120 - 5 = 115`（加时赛最后 5 分钟）

**不触发：**
- 没有制胜球的比赛
- 制胜球不在最后 5 分钟

**示例：**
| 比分 | 制胜球 | 时间 | 绝杀 | 原因 |
|------|--------|------|------|------|
| 1-0 | H1 | 89' | ✓ | 89' ≥ 85 |
| 1-0 | H1 | 55' | ✗ | 55' < 85 |
| 2-1 | H2 | 90+3' | ✓ | 90+3' ≥ 85 |
| 1-0 (加时) | H1 | 118' | ✓ | 118' ≥ 115 |
| 1-0 (加时) | H1 | 96' | ✗ | 96' < 115 |

## 3. 比赛结束时间的判定

根据 `raw_data.periods` 中的 `sort_order` 判断：

| 最高 sort_order | 比赛结束时间 | 说明 |
|:---:|:---:|---|
| ≤ 2 | 90 | 常规时间结束（可能含伤停补时） |
| 3 | 120 | 进入加时赛且加时赛结束 |
| 5 | 120 | 有点球大战（足球比赛在加时赛结束时终止，点球大战不算比赛时间） |

> 注：`sort_order=3` 表示加时赛上半场和下半场都已完成（SportMonks 将两个 15 分钟合并为一个 period）。

## 4. 与旧版逻辑的差异对照

| 项目 | 旧版 v5/v6 | 新版统一 | 变化说明 |
|------|-----------|----------|----------|
| **首开纪录-平局** | v6: 双方各取首球 ✓ / 旧版: 不处理 ✗ | 双方各取首球 | 统一为 v6 逻辑 |
| **绝平球-平局** | v6: 仅非平局 ✗ / signals: 仅平局 ✓ | 仅平局 | 修正 v6 bug |
| **绝平球-时间** | v6: 无时间限制 ✗ / v5: end_minute-5 ✓ | end_minute-5 | 统一时间约束 |
| **制胜球-分差** | 旧版 v6: 不限制分差 ✗ | 必须分差=1 | 新增分差约束 |
| **制胜球-取最后一球** | v6: 取首次领先 ✗ / v5: 取末次领先 ✓ | 取末次领先 | 修正 v6 bug |
| **绝杀-分差** | 旧版 v6: 不限制分差 ✗ | 必须分差=1 | 新增分差约束 |
| **绝杀-时间** | v6: 固定 85 ✗ | 根据加时赛判断 85/115 | 支持加时赛 |

## 5. 代码结构

### 5.1 统一模块

`src/engine/key_events.py` — 唯一的判定逻辑入口

```python
@dataclass
class KeyEventResult:
    first_goal_scorers: list[str]      # 首开纪录球员（1-2人）
    equalizer_scorer: str | None       # 绝平球球员
    winning_goal_scorer: str | None    # 制胜球球员
    late_winner_scorer: str | None     # 绝杀球员
    super_sub_scorers: dict[str, int]  # 超级替补 {player: diff_min}
    penalty_scorers: list[str]         # 点球进球者

def detect_key_events(goals, subs, home_id, away_id, score_home, score_away, periods) -> KeyEventResult:
    ...
```

### 5.2 调用方适配

| 模块 | 调用方式 | 适配说明 |
|------|---------|----------|
| `player_insights_v6.py` | 调用 `detect_key_events` → 填充 `EventBonusesV6` | 原始 events dict → 标准化 goal/subs 列表 |
| `player_insights.py` | 调用 `detect_key_events` → 填充 `EventBonuses` | 原始 events dict → 标准化 goal/subs 列表 |
| `signals.py` | 调用 `detect_key_events` → 填充 `_king_cache` bonus | MatchEvent 对象 → 标准化 goal/subs 列表 |
