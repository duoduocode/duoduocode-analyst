## 1. 设计目标

不再用"进球多=贡献大"的简单逻辑评价球员，而是从 **13 个现代足球分析角度** 出发，对每名球员的 49 项 SportMonks 统计数据做 Z-score / 综合评分 / 标签分类，识别出不同类型的关键贡献者。

### 1.1 设计哲学

- **代码做数学，LLM 做叙事** — 代码保证数据对比零错误，LLM 负责把结果翻译成球迷能读懂的语言
- **队内 Z-score 对比** — 大部分检测器在队内做标准化，因为不同球队体系差异太大
- **综合评分而非单一指标** — 每个检测器是多指标加权合成，权重反映该维度中的相对重要性
- **只依赖可采集指标** — 所有指标均已在 `PLAYER_STAT_MAP` 中映射，`PlayerStats` dataclass 中有对应字段

### 1.2 指标采集现状

| 维度 | 数量 |
|---|---|
| API 返回球员级 type_id | 66 项 |
| `PLAYER_STAT_MAP` 已映射 | 49 项 |
| 检测器实际依赖 | 约 30 项 |
| 不可获取（从检测器移除） | 长传(122/123/27270)、成功抢断(27267)、输掉对抗(1491)、被抢断(94)、导致射门失误(48997)、传中成功率(1533) |

## 2. 核心算法：Z-score 综合评分 (zscore_composite)

D1/D2/D3/D5/D8/D9 使用统一的加权 Z-score 框架：

```
对每项指标 X：
  取队内所有球员的 X 值 → 计算 Z-score = (X - μ) / σ
  贡献分 = Z × weight

综合分 = Σ(所有指标的 贡献分)
```

负向指标（被过人、导致丢球失误等）权重为负数，自动降低综合分。

### D4 节奏控制/节拍器 (Tempo Control)

> **回答什么问题**：谁是球队的节拍器，掌控着比赛节奏？

**特殊算法**：不使用 Z-score，而是基于队内占比的绝对评分：

```python
score = 传球占比 × 100 + 准确率/100 × 2 + 向前传球比 × 10
        + 触球占比 × 100 - 回传比 × 5
```

| 输出指标 | 原始字段 | 类型 | 含义 |
|----------|----------|------|------|
| 传球 | `passes_total` (80) | 原始 | 传球总次数 |
| 传球占比 | — | 计算 | 球员传球 ÷ 全队传球 |
| 准确率 | `passes_accuracy` (1584) | 原始 | 传球成功率 % |
| 三区传球 | `passes_final_third` (27269) | 原始 | 进攻三区传球数 |
| 向前比 | — | 计算 | 三区传球 ÷ 总传球 |
| 回传 | `back_passes` (27272) | 原始 | 回传次数 |
| 触球 | `touches` (120) | 原始 | 触球总数 |
| 触球占比 | — | 计算 | 球员触球 ÷ 全队触球 |

**适用范围**：全部球员（含门将）

| type_id | 原始字段 | 中文名 | 权重 |
|--------:|----------|--------|:---:|
| 78 | `tackles_total` | 抢断 | 1.0 |
| 100 | `tackles_interceptions` | 拦截 | 1.0 |
| 27271 | `ball_recoveries` | 球权回收 | 1.0 |

**第二步**：调和平均排名

```python
进攻排名 ar = 1..N（按进攻分降序）
防守排名 dr = 1..N（按防守分降序）
均衡分 = 2 × ar × dr ÷ (ar + dr)  # 调和平均，越小越均衡
```

**适用范围**：全部球员

### D6 时机价值 (Timing Value)

> **回答什么问题**：谁在最关键的时刻做出了贡献？
> **标签**：关键先生

**算法**：

```python
基础分 = 进球 × 0.5 + 助攻 × 0.3 + 点球进球 × 0.5 + 制造点球 × 0.3
事件加成 = 制胜球 +3.0 / 绝杀 +3.5 / 绝平球 +2.5 / 首开记录 +2.0 / 制造点球 +2.0 / 超级替补 +2.5 / 点球进球 +0.5
总分 = 基础分 + 事件加成
```

**事件奖励一览**：

| 奖励标签 | 触发条件 | 分值 | 来源 |
|----------|---------|:---:|------|
| 制胜球 | 进球使比分反超且最终获胜 | +3.0 | events[type_id=14/16] |
| 绝杀 | 85' 后制胜球 | +3.5 | events[type_id=14/16] |
| 绝平球 | 落后方进球扳平 | +2.5 | events[type_id=14/16] |
| 首开记录 | 获胜方第一个进球 | +2.0 | events[type_id=14/16] |
| 制造点球 | `penalties_won` ≥ 1 | +2.0 | player stats |
| 超级替补 | 替补出场 5 分钟内进球/助攻 | +2.5 | events[type_id=18] |
| 点球进球 | 点球罚进 | +0.5 | events[type_id=16] |

**输出指标**：

| 输出指标 | 原始字段 | 含义 |
|----------|----------|------|
| 进球 | `goals` (52) | |
| 助攻 | `assists` (79) | |
| 点球进球 | `penalties_scored` (111) | |
| 制造点球 | `penalties_won` (115) | |
| 事件加成 | — | 制胜球/绝杀/绝平球/首开记录/制造点球/超级替补/点球进球 |

**适用范围**：仅展示 score > 0 的球员

## 4. 数据流总结

```
run_all_detectors(lineups, home_id, away_id, score_home, score_away, events, end_minute)
    │
    ├── 解析 lineups → PlayerData(id, name, pos, stats, team)
    ├── 计算事件奖励 → EventBonuses(制胜球, 绝杀, 绝平, 首开记录, 制造点球, 超级替补, 点球进球)
    │
    ├── D1  推进价值       → zscore_composite(外场球员, 10项指标含penalties_won)
    ├── D2  防守扫荡       → zscore_composite(外场球员, 7项指标含拦截)
    ├── D3  对抗之王       → zscore_composite(外场球员, 7项指标)
    ├── D4  节奏控制       → 自定义评分(队内占比，8项)
    ├── D5  双向负荷       → 调和平均(进攻8项 + 防守8项)
    ├── D6  时机价值       → 事件奖励 + 基础分
    ├── D7  效率与产量背离 → per-90 速率评分
    ├── D8  角色偏离度     → 分位置非典型指标
    ├── D9  连接器         → zscore_composite(外场球员, 5项指标，无长传)
    ├── D10 终结质量       → 非点球 xG/shot + xGOT + SP
    ├── D11 xG背离度       → |进球 - xG| + 标签
    ├── D12 纯终结者       → 进球占比 + 转化率 + xG支配力
    └── D13 终结能力       → 合并D10+D11+D12 + 关键进球
```
