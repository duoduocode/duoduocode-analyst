# 战术文章命名 & 球员推荐文章生成 — 技术方案

## 一、总体说明

在现有分析流水线基础上，新增两个 LLM 驱动的环节并集成到赛后报告管道中。

| 环节 | 名称 | 输入来源 | 输出 |
|------|------|----------|------|
| 1 | 战术文章取名 | 战术分析结果 + 压迫分析结果 + 关键事件 | 10 个文章标题 + 简短理由（按角度分布） |
| 2 | 球员推荐文章筛选 | 比赛结果 + 战术报告 + 球员贡献卡片 + 赛事信息 + 球员新闻（SportMonks + LLM 搜索） | 球员推荐 Markdown 表格 + HTML 渲染 |

---

## 二、环节一：战术文章取名

### 2.1 输入数据

复用现有流水线数据，不新增数据采集：
- **战术分析文本**：`prompts/tactical.yaml` 生成的「战术画像 / 演绎 / 验证 / 博弈 / 定论」五段叙事
- **压迫分析文本**：`prompts/pressing.yaml` 生成的压迫叙事
- **关键事件时间线**：`raw.events` 中过滤进球 / 红牌 / 点球 / 绝杀等关键事件
- **比赛元信息**：双方队名、比分、半场/加时/点球、赛事名称（`raw.stage_info.name`）

### 2.2 实现方式

新增 LLM 提示词 `prompts/article_naming.yaml`，通过 `PromptLoader` 加载，LLM 使用 **DeepSeek**（复用项目现有配置）。

**SYSTEM**：专业足球编辑 / 标题策划人格，结合战术分析、压迫分析和比赛结果起标题。标题要抓人但不标题党，兼顾战术深度与传播属性。

**USER 模板（Jinja2）**：

```
比赛信息：{match_context}（赛事、队名、比分、半场/加时/点球详情）
战术分析摘要：{tactical_summary}（五段叙事全文或摘要）
压迫分析摘要：{pressing_summary}
关键事件：{key_events}（进球球员、分钟数、事件类型）
```

### 2.3 标题多样性约束

10 个标题按 **三个角度** 分布，在 SYSTEM prompt 中硬约束：

| 角度 | 最少数量 | 说明 |
|------|----------|------|
| 战术向 | ≥ 2 | 聚焦战术博弈、体系对抗、阵型克制等，如《控球72%的虚无》 |
| 人物向 | ≥ 2 | 聚焦关键球员表现、个人英雄时刻、宿命对决等，如《一个人的反击》 |
| 数据向 | ≥ 2 | 聚焦数据异常、统计亮点、xG背离等，如《2.8 xG 换不来一个进球》 |
| 自由角度 | 剩余 | 不限，可融合多种角度 |

**输出格式要求**：

```
【战术向】
1.《标题一》— 理由简述(20字以内)
2.《标题二》— 理由简述

【人物向】
3.《标题三》— 理由简述
4.《标题四》— 理由简述

【数据向】
5.《标题五》— 理由简述
6.《标题六》— 理由简述

【自由角度】
7.《标题七》— 理由简述
8.《标题八》— 理由简述
9.《标题九》— 理由简述
10.《标题十》— 理由简述
```

### 2.4 新增/修改文件

| 文件 | 操作 | 说明 |
|------|------|------|
| `prompts/article_naming.yaml` | **新增** | LLM 提示词模板，含角度约束 + few-shot 示例 |
| `src/composer/article_naming_prompt.py` | **新增** | Prompt 组装模块（仿 `tactical_prompt.py`） |
| `src/reporter/build_report.py` | 修改 | 新增「文章标题推荐」Section |
| `build_player_analysis.py` | 修改 | 串联调用、保存结果 |

### 2.5 调用时机

在战术分析 + 压迫分析 LLM 调用完成后，将两份输出文本 + 关键事件送入 `article_naming` prompt，调用 1 次 DeepSeek LLM。

## 三、环节二：球员推荐文章筛选

### 3.1 输入数据

| 数据 | 来源 | 说明 |
|------|------|------|
| 比赛基本信息 | `raw` | 队名、比分、半场/加时/点球 |
| 赛事信息 | `raw.stage_info.name` | 世界杯 / 英超 / 欧冠 / 亚洲杯等 |
| 战术分析文本 | 现有战术分析输出 | 五段叙事全文 |
| 压迫分析文本 | 现有压迫分析输出 | 压迫叙事全文 |
| 球员贡献数据 | `run_all_detectors()` 结果 | 检测器标签、得分、Top 指标、事件加成 |
| 球员 LLM 点评 | `player_analysis.yaml` 输出 | 60-80 字赛后评语 |
| 球员基础信息 | `raw.home_players / away_players` | 姓名、位置、出场时间、关键事件 |
| **球员最新报道** | **SportMonks News API + LLM 联网搜索** | 转会传闻、伤病、国家队动态、近期表现 |

### 3.2 球员新闻获取方案

采用 **双源融合** 策略，按优先级依次尝试：

#### 第一源：SportMonks News API

在 `SportMonksClient` 中新增两个方法：

```python

    """拉取球队相关新闻摘要"""
    # GET /football/news?filters=team:{team_id}&per_page={limit}

def get_newsfeeds(self, team_ids: list[int], limit: int = 20) -> list[dict]:
    """拉取多队新闻流"""
    # GET /football/newsfeeds?filters=team:{team_ids}&per_page={limit}
```

返回字段：`title`、`content`（摘要）、`created_at`、`url`

- 对候选球员姓名做关键词匹配，提取相关新闻摘要（每条 ≤ 200 字）
- 每人最多附带 3 条相关新闻

#### 第二源：DeepSeek 联网搜索（补充）

当 SportMonks 返回的新闻数量不足或相关性不高时：

1. 构造搜索 query：`"{球员姓名} {球队名} 足球 新闻 最新"`
2. 通过 DeepSeek 的联网搜索能力（或 `web_search` tool）获取补充信息
3. 将搜索结果摘要化（每条 ≤ 150 字）合并到球员新闻卡片中

**注意**：联网搜索作为可选增强，如果 SportMonks News API 不可用或配额不足，可降级为纯比赛数据模式（仅靠贡献数据 + 赛事背景撰写）。

### 3.3 筛选逻辑（两阶段）

#### 第一阶段：Python 预筛选

从双方球员中筛出候选池（预计 5-10 人）：

| 规则 | 逻辑 |
|------|------|
| 官方 MVP | `man_of_match == True` — 直接入选，权重 3 |
| 关键事件挂钩 | 进球 / 助攻 / 绝杀 / 扑点 / 造红牌 — 权重 2 |
| 检测器 Top3 | 任一检测器队内前 3 — 权重 1.5 / 标签 |
| 门将神扑 | 扑救 ≥ 5 次 or `saves_inside_box ≥ 3` or 扑出点球 |
| 替补奇兵 | 替补登场且贡献进球/助攻 |
| 争议/转折 | 红牌 / 送点 / 乌龙 / 失误致失球 — 权重 1 |

**文章价值分**：

```
value = 3×MVP + 2×(关键事件数) + 1.5×(Top3标签数) + 1×替补奇兵 + 1×争议事件
```

按分值降序取前 5-8 人送入 LLM。

新增文件：`src/engine/player_feature_selector.py`

#### 第二阶段：LLM 评估与推荐

新增 `prompts/player_feature_recommend.yaml`，使用 **DeepSeek**。

**SYSTEM**：资深足球媒体编辑，为比赛挖掘值得写人物特稿的球员，有数据思维也有故事嗅觉。

**USER 模板提供**：
- 比赛上下文（赛事、比分、赛况概述）
- 战术分析摘要
- 球员新闻卡片（SportMonks + LLM 搜索的融合结果）
- 候选球员卡片（每人）：
  - 姓名、位置、球队、出场时间
  - 贡献维度标签 + Top 指标 + 数值
  - 关键事件（进球/助攻/红黄牌等）
  - LLM 60-80 字赛后点评
  - 赛事背景标签（世界杯 = 高权重）

**输出格式**（Markdown，可直接发布）：

```markdown
# {赛事名称} | {主队} vs {客队} — 球员人物特稿推荐

## 一、比赛概述
（战术分析摘要 + 比分 + 赛况简述，100-150字）

## 二、推荐球员人物特稿

### 球员姓名 | 所属球队 | 位置 | ⭐推荐指数 (1-5星)

**文章看点**：(1-2句话，说清为什么值得写)
**故事线**：(与赛事背景、球员个人经历/新闻、比赛走势的关联)
**文章标题备选**：
1. 《标题一》
2. 《标题二》
3. 《标题三》
4. 《标题四》
5. 《标题五》
**文章大纲**：
- 开篇：(用比赛关键瞬间切入)
- 数据拆解：(引用具体数据讲贡献)
- 战术角色：(在体系中的定位和影响力)
- 故事纵深：(结合赛事背景/个人故事/近期新闻/历史对比)
- 收尾：(总结评价，点出意义)

---
```

### 3.5 调用时机

在现有 `process_match()` 末尾（卡片 + Excel 完成后）：

1. 拉取 SportMonks 新闻 + LLM 搜索补充（可与环节一并行）
2. 调用 `player_feature_selector` 预筛选候选
3. 调用环节一获取 10 个标题（与环节二并行无依赖时可并行）
4. 调用环节二获取推荐 Markdown

## 四、Prompt 设计要点

### 4.1 article_naming.yaml

- 角度约束：在 SYSTEM 中明确要求战术向 ≥ 2、人物向 ≥ 2、数据向 ≥ 2
- Few-shot 示例（每角度 2 个）：

```
【战术向示例】
《控球72%的虚无》— 西班牙式传控遇铁桶阵的终极困境
《高位防线的葬礼》— 三次被打穿的战术解剖

【人物向示例】
《一个人的反击》— 姆巴佩的11次冲刺如何撕碎体系
《第93分钟的救赎》— 替补奇兵改写命运的瞬间

【数据向示例】
《2.8 xG 换不来一个进球》— 射门效率崩塌的真相
《传球成功率91% vs 输球》— 无效传控的数据悖论
```

### 4.2 player_feature_recommend.yaml

- SYSTEM：作为资深人物特稿编辑，有数据思维和故事嗅觉
- 对每位候选给出独立推荐分析，若某球员"不值得推荐"可给出低星并说明原因
- 大纲固定五段结构（开篇 / 数据 / 战术 / 纵深 / 收尾）

## 五、产出物

### 5.1 HTML 报告（嵌入现有 `build_report_v3_html`）

新增两个 Section：

- **文章标题推荐**：按角度分组卡片网格展示 10 个标题 + 理由
- **球员人物特稿推荐**：推荐指数 ≥ 3 星的球员卡片（头像/姓名/看点/5标题备选/大纲折叠展开）

### 5.2 独立 Markdown 文件

输出到 `output/{match_id}_{hname}_vs_{aname}/player_features.md`：

- 环节一产出：10 个标题 + 理由（作为开篇）
- 环节二产出：完整 Markdown 格式的球员推荐文章表格（3.3 节输出格式即为最终文档结构）
- 可直接发布或存入 CMS

### 5.3 输出目录结构（新增部分以 `+` 标记）

```
output/{match_id}_teamA_vs_teamB/
  player_cards/
  player_insights.xlsx
+ article_titles.json          # 环节一结构化输出（10个标题+理由+角度）
+ player_features.md           # 环节二 Markdown 输出
```

## 七、技术决策总结

| 决策项 | 结论 |
|--------|------|
| 球员新闻来源 | SportMonks News API 为主 + DeepSeek 联网搜索为补充，API 不可用时降级为纯数据模式 |
| 推荐表格输出 | HTML 报告中嵌入 + 独立 Markdown 文件 (`player_features.md`) |
| LLM 模型 | DeepSeek（复用项目现有配置） |
| 标题多样性 | 战术向 ≥ 2、人物向 ≥ 2、数据向 ≥ 2，自由角度填充至 10 个 |
| 存放路径 | 方案文档：`design/`；代码：按现有项目结构 |
