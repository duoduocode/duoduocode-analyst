# 比赛战术分析板块设计

> 设计日期：2026-06-08 | 数据来源：SportMonks V3 球队级 45 项 + 球员级 66 项

---

## 1. 设计目标

每一场足球比赛都是两种足球哲学的碰撞。战术分析板块的核心任务是：

1. **解码战术语言** — 从数据逆向推导两队赛前的战术部署
2. **验证执行效果** — 战术是否成功落地？是否被对手破解？
3. **发现隐藏矛盾** — 战术意图与实际产出的背离，制造话题感
4. **对比制造张力** — 用直接对比揭示双方本质差异

输出形式：**五段式战术叙事**，每段含数据论点 + LLM 故事化表达。

## 3. 第一维：进攻体系 — 他们怎么攻？

### 3.1 建攻方式指数 (Build-Up Style Index)

用**长传比**区分直接打法 vs 传控打法。

```
长传比 = 长传次数 / 总传球次数

判定：
  > 0.22  → "直来直往型"：快速通过中场，追求纵向穿透
  0.15~0.22 → "混合型"：视情况切换长短传节奏
  < 0.15 → "绣花型"：耐心倒脚，用传球拆防线
```

**话题钩子**：`{team} 平均每次进攻触球 {avg_touches_per_attack} 次——{对立描述}`

### 3.2 进攻宽度偏好 (Width Preference)

```
传中偏好度 = 传中次数 / 总传球次数
边路依赖度 = (传中次数 + 长传次数) / 总传球次数

判定：
  传中偏好度 > 0.12 → "边路轰炸型"
  边路依赖度 < 0.15 且 短传占比 > 0.85 → "中路渗透型"
  否则 → "均衡分布型"
```

**话题钩子**：对比两队的边路依赖度差异，差异 > 1.5 倍时触发"宽度对决"叙事

### 3.3 射门质量偏好 (Shot Quality Profile)

```
禁区内射门比 = 禁区内射门 / 总射门
每射 xG = xG / 总射门
射门转化率 = 进球 / 总射门

矩阵判定（每射 xG × 禁区内射门比）：
  高×高 → "禁区猎手"（耐心创造高价值射门）
  高×低 → "远射大队"（禁区外高威胁射门有谱）
  低×高 → "禁区磨豆腐"（进去了但射门质量差）
  低×低 → "浪射成性"（低效进攻体系）
```

### 3.4 创造力指数 (Creativity Index)

```
创造力指数 = (关键传球 + 绝佳机会 + 直塞) / 总传球次数 × 100

判定：
  > 5.0 → "每脚传球暗藏杀机"
  2.5~5.0 → "创造力中规中矩"
  < 2.5 → "创造力匮乏，依赖个人闪光"
```

**核心指标**（依托球员级汇总）：

| 指标 | 球队级 type_id | 数据源 |
|------|:---:|------|
| 长传 | 62 | 球队 stats |
| 短传 | 63 | 球队 stats |
| 传中 | 98 | 球队 stats |
| 关键传球 | 117 | 球员 `passes_key` 汇总（球队级 ⚠️） |
| 绝佳机会 | 580 | 球员 `big_chances_created` 汇总 |
| xG | — | 球员 `xg` 汇总 |
| 禁区内射门 | 49 | 球队 stats |
| 禁区外射门 | 50 | 球队 stats |

## 4. 第二维：防守体系 — 他们怎么防？

### 4.1 防线高度推断 (Defensive Line Height)

SportMonks 不直接提供防线高度数据，但可以通过**越位陷阱效果**和**抢断位置分布**间接推断。

```
越位陷阱活跃度 = 对方越位次数（球队 stats type_id=51）

辅证指标（球员级汇总）：
  高位逼抢指数 = 中前场球员抢断次数 / 全队抢断 × 100

判定：
  越位 > 4 且 高位逼抢指数 > 50% → "高位防线，造越位逼抢一体"
  越位 > 4 且 高位逼抢指数 < 50% → "高位但抢不下，防线虚高（危险）"
  越位 < 2 且 解围 > 20 → "收缩蹲坑，死守禁区"
  越位 2~4 → "中等防线，收缩有序"
```

**数据源**：

| 指标 | 来源 | 备注 |
|------|------|------|
| 对方越位次数 | 球队 stats type_id=51 | 对方越位即本方造越位 |
| 解围 | 球员 `clearances` 汇总 | |
| 抢断 | 球员 `tackles_total` 汇总 | 按位置区分中前场/后场 |

### 4.2 压迫强度 (Press Intensity)

```
压迫强度 = 抢断次数 / 对手触球次数 × 100
抢断成功率 = 成功抢断 / 总抢断

二维判定：
  高压迫 + 高成功率 → "高位猎犬"（压迫体系成熟）
  高压迫 + 低成功率 → "乱枪打鸟"（逼抢意愿强但组织差）
  低压迫 + 高成功率 → "精确打击"（选择性上抢，效率极高）
  低压迫 + 低成功率 → "纸糊防线"（既不抢也抢不下来）
```

### 4.3 防守区域偏好 (Defensive Territory)

```
空中防守占比 = (解围 + 摘高球) / (解围 + 摘高球 + 抢断 + 拦截) × 100

判定：
  > 60% → "空中堡垒"（依赖头球解围，应对传中轰炸）
  < 30% → "地面扫荡"（依赖抢断拦截，应对地面渗透）
```

### 4.4 纪律风险评估 (Discipline Risk)

```
战术犯规比 = 犯规次数 / 黄牌数

判定：
  > 5.0 → "老练的犯规者"（犯规多但拿牌少，战术犯规成熟）
  3.0~5.0 → "正常纪律水平"
  < 2.5 → "伐木工"（每犯必黄，动作粗野或被裁判盯上）
```

**数据源**：

| 指标 | type_id | 数据源 |
|------|:---:|------|
| 抢断 | 78 | 球队 stats |
| 成功抢断 | — | 球员 `tackles_won` 汇总 |
| 拦截 | 100 | 球队 stats |
| 解围 | — | 球员 `clearances` 汇总 |
| 犯规/黄牌 | 56/84 | 球队 stats |

## 5. 第三维：控球效率 — 控住了有用吗？

### 5.1 控球投资回报率 (Possession ROI)

这是本板块最具**话题性**的指标，直接回答"控球多的一方是否值得"。

```
每 1% 控球的 xG 产出 = xG / 控球率 × 1

判定：
  > 0.035 → "高效控球"（每 1% 控球产出 0.035 xG，控球有杀伤）
  0.020~0.035 → "标准控球回报"
  < 0.020 → "控球浪费"（占据大量球权却无法转化为射门质量）
```

**对比钩子**：
- 控球少但 xG 高 → "反控球辩证法：{少控球方}用 {x}% 的控球创造了 {y}% 的 xG"
- 控球多但 xG 低 → "国王的新衣：{多控球方}控球 {x}% 却只创造 {y} xG"

### 5.2 传球穿透力 (Pass Penetration)

```
穿透指数 = 关键传球次数 / 总传球次数 × 100
平均每次射门的传球数 = 总传球 / 总射门（越低越直接）
```

**对比钩子**：`"A 队平均 {passes_per_shot} 脚传球换一脚射门，B 队只需 {passes_per_shot} 脚——进攻节奏差了一倍"`

### 5.3 危险进攻转化率

```
危险进攻转化率 = 射门次数 / 危险进攻次数 × 100

判定：
  > 40% → "每两次危险进攻就形成射门，最后30米效率极高"
  25~40% → "正常转化"
  < 25% → "危险进攻名不副实，最后一传始终找不到人"
```

## 6. 第四维：对抗强度 — 身体层面的胜负

### 6.1 地面对抗格局 (Ground Duel Landscape)

```
对抗成功率 = 赢得对抗 / 总对抗 × 100

按区域分析（依托球员位置）：
  前场对抗率 = 前锋/中场对抗占比
  中场控制力 = 中场球员对抗成功率 vs 对手中场
```

### 6.2 空中霸权 (Aerial Supremacy)

```
空中成功率 = 赢得空中 / (赢得空中 + 输掉空中) × 100

判定：
  > 60% → "空中霸权"（对手传中基本上不了手）
  < 38% → "空中筛子"（每当球飞过来就心跳加速）
```

### 6.3 盘带穿透力 (Dribble Penetration)

```
盘带成功率 = 成功过人 / 尝试过人 × 100
场均过人被捕率 = 被抢断 / (成功过人 + 被抢断) × 100

判定矩阵：
  高成功率 + 低被捕率 → "过人如麻"（防线被个体能力撕裂）
  高成功率 + 高被捕率 → "高风险盘带"（好看但不安全）
  低成功率 → "过人黑洞"（试图盘带但频频丢球）
```

## 7. 第五维：节奏管理 — 谁在掌控比赛呼吸？

### 7.1 时段节奏分布

依托 SportMonks 的 `periods.statistics` 数据，按上下半场（甚至分时段）对比。

```
下半场加速率 = (下半场射门 - 上半场射门) / 上半场射门 × 100

判定：
  > 50% → "下半场猛冲型"（中场调整效果显著或上半场蓄力）
  < -30% → "体力衰竭型"（上半场猛攻后下半场无可战之兵）
  两者之间 → "平稳节奏型"
```

### 7.2 领先/落后行为模式

分析关键进球前后的攻防数据变化，由 `compute_event_bonuses_v6` 和 events timeline 提供。

```
领先后的保守指数 = (领先前射门率 - 领先后射门率) / 领先前射门率 × 100

判定：
  领先后射门率降 > 40% → "鸣金收兵"（主动回收）
  领先后射门率升 > 10% → "穷追猛打"（打顺了不收手）
  控制在 ±20% → "不为所动"（领先不改变节奏）
```

### 7.3 时间压迫下的攻防比

```
最后 15 分钟攻防比 = 进攻次数 / 被射门次数

判定：
  > 2.5 → "末日冲锋"（落后方全线压上，有压迫感）
  < 0.6 → "死守模式"（领先方全线退防）
  1.0~2.0 → "你来我往"（双方还在踢自己的比赛）
```

## 8. 第六维：教练博弈 — 谁在棋局上赢了？

### 8.1 换人意图与效果

依托 `src/engine/sub_impact.py` 的设计：

| 换人时机 | 意图推断 | 验证指标 |
|:---:|------|------|
| < 30' | 伤病被迫 / 战术重大失误 | 换人后球队指标是否回暖 |
| 46'-60' | 中场纠错，主动求变 | 下半场前 15 分钟趋势对比 |
| 60'-75' | 对位调整，维持强度 | 被换下球员贡献维度 |
| 75'-85' | 战术转向（追分/死守） | 锋线/后卫换人方向 |
| > 85' | 拖延时间 | 换人后净时间变化 |

**核心数据**：换下球员的 v6 贡献向量 → 判断"换下最强一环"还是"换下短板"

### 8.2 战术克制分析

```
战术克制得分 = Σ(我方战术优势方向 vs 对手防守弱点的匹配度)

示例匹配：
  边路轰炸型进攻 vs 地面扫荡型防守（不依赖头球解围）→ +2 克制
  直来直往型进攻 vs 高位逼抢（快速通过中场避开逼抢）→ +1 克制
  禁区猎手 vs 空中堡垒（低效的传中轰炸 vs 头球高手）→ +1 克制
```

### 8.3 战术矛盾点（话题性最强）

用四象限图对比双方的**战术意图 vs 实际产出**：

```
         高 xG
          ▲
          │  B 队："控球 32%，xG 1.87"
    低控球│  ← 反控球哲学：不控球反而高效
          │
  ────────┼────────→ 高控球
          │  A 队："控球 68%，xG 0.91"
          │  ← 控球浪费，国王的新衣
          ▼
         低 xG
```

### 9.2 Layer 2：LLM 叙事 → `prompts/tactical_analysis.yaml`

六维数据输入 → LLM 输出 5 段叙事：

1. **【战术预判】** — 赛前预期的战术对决画像
2. **【攻防解码】** — 一方怎么攻、另一方怎么守，谁占了上风
3. **【效率悖论】** — 控球与 xG 的矛盾，谁"看起来在踢球"、谁"真正在踢球"
4. **【身体对抗】** — 地面 + 空中 + 盘带的胜负分布
5. **【棋盘博弈】** — 换人意图、战术调整、克制关系、战术定论

### 9.3 Layer 3：报告拼装 → 嵌入现有 v3 架构

战术分析板块位于 v3 架构的**第四段「战术解码」**，替代原来的简化版。

## 10. 话题感设计

每个维度的判定结果都设计了一个**话题钩子**（hook），格式为 `"{一方} 的 {战术特点} 与 {另一方} 的 {对立特点} — {结果}"`：

| 维度 | 话题钩子示例 |
|------|------|
| 进攻体系 | "PSG 用 9% 的长传率绣花，拜仁用 24% 的长传率直插心脏——两种哲学，一种信念" |
| 控球效率 | "控球 68% 的 PSG 只创造 0.91 xG，控球 32% 的拜仁创造 1.87 xG——国王真的穿了衣服吗？" |
| 防守体系 | "高位逼抢的 PSG 每 7.3 分钟抢断一次，蹲坑的拜仁解围了 28 脚——谁在害怕？" |
| 对抗强度 | "拜仁赢得了 56% 的空中对抗，阿森纳赢得了 62% 的地面对抗——天空属于他们，地面属于我们" |
| 教练博弈 | "阿尔特塔 60 分钟连换两人，恩里克按兵不动——一个在出题，一个不想答" |

```markdown
# PSG 1 vs Arsenal 1 (点球 3-4)：控球68%是国王的新衣，
# 阿森纳只剩一脚射正却带走胜利

---

## 导读·战术速览

![六维对比](六维雷达图.png)

**巴黎圣日耳曼**：控球碾压 + 地面渗透，但 xG 产出低效——典型的"控球绣花"。  
**阿森纳**：放弃控球蹲坑反击，用 32% 控球创造等量 xG——"不控球的效率王者"。

---

## 一、进攻体系：绣花 vs 直插

PSG 全场传球 887 脚、短传占比 78%，是典型的传控打法（长传比仅 0.07）；阿森纳传球 285 脚、长传比 0.14，每次推进更追求纵向穿透。

| 指标 | PSG | 阿森纳 | 差异 |
|------|:---:|:---:|------|
| 总传球 | 887 | 285 | PSG 多 211% |
| 长传比 | 7.1% | 14.4% | 阿森纳更直接 |
| 传中偏好度 | 3.0% | 3.9% | 均非边路轰炸型 |
| 总射门 / 禁区内 | 21 / 12 | 7 / 5 | PSG 压倒性 |
| xG / 每射 xG | 2.17 / 0.10 | 0.91 / 0.13 | 阿森纳单脚更有威胁 |
| 关键传球 | 15 | 7 | PSG 创造力领先 |

**解读**：PSG 把比赛踢成了半场攻防演练，但每脚射门的预期进球（0.10）反而不如阿森纳（0.13）——阿森纳虽然只射了 7 脚，但每脚都在更有威胁的位置。这就是"高控球不等于高质量"。

![传球结构对比](传球结构.png)

PSG 的传球网络像一张密织的网，短传 692 脚占 78%；阿森纳则是一根利箭，用更少的传递直接找到前锋。两队代表了控球哲学的两极。

---

## 二、防守体系：高位逼抢 vs 收缩蹲坑

PSG 整个防守体系前推——对方越位 4 次说明造越位陷阱活跃，抢断 8 次中中前场占比 62%，是典型的"高位逼抢+造越位"一体设计。阿森纳的战术更多是"收缩—拦截—解围"：全场解围 21 次、拦截 7 次，标准的蹲坑型防守。

| 指标 | PSG | 阿森纳 | 解读 |
|------|:---:|:---:|------|
| 造越位（对方越位次数） | 4 | 1 | PSG 防线更高 |
| 抢断 / 中前场占比 | 8 / 62% | 10 / 45% | PSG 高位逼抢 |
| 拦截 | 8 | 7 | 相当 |
| 解围 | 15 | 21 | 阿森纳蹲坑 |
| 犯规 / 黄牌 | 11 / 2 | 17 / 4 | 阿森纳用犯规换节奏 |

![对抗热力图](对抗热力图.png)

**解读**：PSG 的防守哲学是"把火燃到对方半场"——抢断发生在中前场的比例高达 62%，这意味着他们试图在对手刚拿到球时就掐灭进攻。但阿森纳的应对很沉稳：收缩禁区、用 21 脚解围和 7 次拦截织成一张保护网。

---

## 三、效率悖论：国王的新衣

这是本场比赛最核心的洞察：

| 指标 | PSG | 阿森纳 |
|------|:---:|:---:|
| 控球率 | 68% | 32% |
| xG | 2.17 | 0.91 |
| 每 1% 控球产量的 xG | **0.032** | **0.028** |
| 结论 | 正常控球回报 | 正常控球回报 |

**PSG 控球 68%，创造了 2.17 xG；阿森纳控球 32%，创造了 0.91 xG。** 换算每 1% 控球的 xG 产出，PSG 是 0.032，阿森纳是 0.028——PSG 确实控得更值钱，但阿森纳用更少的球权创造了接近的产出效率。

![控球-xG](控球xG四象限.png)

> **定论**：不是国王的新衣，而是两种逻辑都成立了——PSG 靠控球碾压创造大量 xG（虽然实际只进 1 球），阿森纳靠高质量机会保持持平。

---

## 四、对抗与节奏：中场争夺定胜负

| 指标 | PSG | 阿森纳 |
|------|:---:|:---:|
| 对抗成功率 | 44% | 47% |
| 空中成功率 | 42% | 58% |
| 盘带成功率 | 50% (4/8) | 75% (6/8) |
| 上半场射门 / 下半场射门 | 15 / 6 | 4 / 3 |

**阿森纳赢得了空中、盘带和对抗三个维度的优势**，虽然次数少但效率高。PSG 下半场射门从 15 次锐减至 6 次——体能下降加枪手收缩防守压缩了空间。

## 五、教练博弈：恩里克的困惑

**换人对比**：PSG 用满 6 次换人，5 人在第 60-85 分钟之间上场，属于"对位调整+维持强度"的标准套路。阿森纳也用满 5 次换人，时间类似。

**最大信号**：阿森纳换上若日尼奥（中场）和梅里诺（中场）——用更多人守住中场屏障。PSG 换下门德斯和李刚仁——换下进攻创造者，但阿森西奥和李刚仁本身就是替补上场后被换下，这说明恩里克对自己的进攻部署并不满意。

> **战术克制结论**：阿尔特塔的"蹲坑+高效反击"策略成功了——面对 PSG 的 887 脚传球，阿森纳用更少的犯规代价完成了更多的有效防守。

## 结语

PSG 踢得更漂亮、更主动、更控制，但枪手用纪律和效率在巴黎全身而退。**控球是手段，不是目的**——这场比赛是这句话的最佳注脚。

│ 5. 输出到 output/         │
│    ├── 战术分析.md        │  ← 复制到公众号
│    └── charts/*.png       │  ← 上传到公众号素材库
└──────────────────────────┘
```

> 步骤 3 和 4 可并行执行：图片渲染不依赖 LLM 结果。

### 15.6 中间 Excel 审查文件

在 Markdown 和图片输出之前，先输出一份结构化 Excel 文件，作为**人工审查与修改的中间层**。

#### 15.6.0 设计理念

```
 代码计算 ──→ Excel（数据+叙事）──→ 人工审查修改 ──→ 重新生成 Markdown
               ▲                        │
               │    可多次迭代           │
               └────────────────────────┘
```

- 代码只写 Excel（不直接写 Markdown）
- 用户打开 Excel 审查：修正 LLM 措辞、调整叙事角度、补充个人观点
- 修改完成后运行 `--from-excel` 重新生成最终 Markdown
- Excel 版本可归档，便于对比不同版本的人工修改

#### 15.6.1 Sheet 结构

#### 15.6.3 使用方法

**第一步：代码生成 Excel**

```bash
python run_tactical.py 19683241 --mode excel
```

输出：`output/19683241/tactical_review.xlsx`

此时：
- D/E 列（原始值）已填充
- F 列（导出指标）已通过公式计算
- F 列（LLM 叙事）已由大模型生成
- G 列（用户覆盖）为空
- H 列（最终使用）= F 列的值
- I 列（校验状态）标注了 LLM 叙事中引用的数值是否能在 D/E 列找到

**第二步：人工审查修改**

打开 Excel，审查 LLM 叙事文本：
- 如果满意：不动 G 列
- 如果修改措辞：在 G 列填写修改后的版本
- 如果补充个人观点：在 G 列追加内容
- 如果某句话没有数据支撑：I 列会标红，应考虑修改或增补数据

**第三步：从 Excel 重新生成 Markdown**

```bash
python run_tactical.py 19683241 --mode md --from-excel
```

读取 Excel 中 H 列（最终使用）的内容，生成 `output/19683241/战术分析.md`。

如果只修改了某些 Sheet 的叙事，也可以只重新生成该段落：

```bash
python run_tactical.py 19683241 --mode md --from-excel --section attacking
```

### 15.7 公众号发布 Checklist

发布一篇战术分析文章的实际操作步骤：

1. 运行 `python run_tactical.py {match_id}`
2. 打开 `output/{match_id}/战术分析.md`，复制全文
3. 粘贴到微信公众号编辑器
4. 逐一插入 5 张配图到对应段落位置
5. 设置封面（可选，用六维雷达图或双方队徽拼接）
6. 添加"阅读原文"链接（可选）
7. 预览 → 发布

> 全程无需手动写一个字。所有文字由 LLM 基于计算数据生成，所有图表由 Matplotlib 自动渲染。

### 15.8 LLM 硬约束

为确保"每句话都有数据支撑"，在 `prompts/tactical_analysis.yaml` 中增加以下约束：

```yaml
constraints:
  - "每段叙事至少引用 2 个具体数值，数值来自输入数据，不得编造"
  - "禁止使用'表现出色''状态火热'等模糊评价，必须换成'xG 0.13/射'等具体数据"
  - "对比句式强制使用'{甲方}{数字} vs {乙方}{数字}'格式，不允许只说一方"
  - "每个章的结论必须回到数据表中的一个数值"
  - "如果某项数据为 0 或缺失，不要提及该项维度，不要推测"
```
